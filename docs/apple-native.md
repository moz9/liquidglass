# Apple: нативный путь и версии

Проверено по источникам Apple 2026-09-30. Это практический маршрут, не каталог всех API. Сигнатуры и availability сверяй с SDK проекта; документация последней версии может описывать более новый overload.

## 26 и 27

| Ориентир | Что учитывать |
|---|---|
| iOS/iPadOS 26, macOS 26 | Исходный Liquid Glass: адаптивная линза и функциональный слой управления; взаимодействие со scroll edge. Не фиксируй вид по первому beta-скриншоту: минорная версия и настройки тоже влияют. |
| Семейство 27 | Сильнее рассеивается сложный фон; тёмная кромка и яркие specular highlights усиливают разделение. Пользователь регулирует внешний вид от ultra clear до tinted. Уже использующие Liquid Glass приложения получают обновлённый материал при запуске на новой ОС. |
| macOS/iPadOS 27 | Sidebar доходит до краёв; более однородная верхняя панель поддерживает читаемость при прокрутке. Не навязывай плавающий inset-sidebar образца 26. У Mac согласованы более тесные радиусы окон. |

Источник различий 27: [Platforms State of the Union, WWDC26](https://developer.apple.com/videos/play/wwdc2026/102/). Эти качественные изменения не задают точных blur/alpha/radius. Не придумывай «токены Apple 27» по текстовому описанию.

В SwiftUI 27 Apple также описывает интерактивное стекло custom controls на Mac с реакцией на мышь и состояние неактивного окна на iPad. Проверяй клавиатурный и pointer-ввод, активное/неактивное окно и resize; одинаковый модификатор не гарантирует одинаковую реакцию на всех ОС. [What’s new in SwiftUI, WWDC26](https://developer.apple.com/videos/play/wwdc2026/269/).

## Порядок внедрения

1. Собери исходный проект с поддерживаемым SDK, запусти на целевой ОС. Посмотри, что уже оформлено системой. Снимай исходное состояние перед изменениями.
2. Сохраняй `NavigationStack`, `NavigationSplitView`, `TabView`, toolbars, menus, popovers, sheets и системные controls. Устрани только те самописные фоны/appearance overrides, которые мешают требуемому системному материалу. Не удаляй бренд и настройки поведения без причины.
3. Для отдельной стеклянной кнопки выбери `.buttonStyle(.glass)` или `.glassProminent`. В системном toolbar дополнительный material обычно не нужен. Для custom view — `glassEffect`, а интерактивность включай только у действительно интерактивного элемента.
4. Проверь safe areas, доступность контента под панелями и scroll edge. `backgroundExtensionEffect()` полезен для продолжения фона в системной компоновке; это не разрешение скрывать важные элементы или безусловно применять `ignoresSafeArea()`.

Основание: [Adopting Liquid Glass](https://developer.apple.com/documentation/TechnologyOverviews/adopting-liquid-glass), [Build a SwiftUI app with the new design](https://developer.apple.com/videos/play/wwdc2025/323/).

В плотных Mac-интерфейсах Mini/Small/Medium controls сохраняют rounded rectangles; Large и X-Large используют капсулы. Это описанное Apple различие уже в 26: не заменяй компактный inspector набором крупных мобильных капсул. [Get to know the new design system](https://developer.apple.com/videos/play/wwdc2025/356/).

## Custom SwiftUI

- `Glass.regular` — обычный исходный выбор. `clear` предназначен для особого контекста вроде медиа с обеспеченным контрастом; это не глобальная настройка «лучшего стекла». Имена `Thick`, `Solid`, `Tinted` из JSON репозитория не являются перечнем вариантов `Glass`.
- Форму задавай по роли и размеру компонента. Выполни layout/padding до применения материала. Foreground остаётся читаемым и семантическим; не добавляй свой blur поверх нативного стекла.
- `GlassEffectContainer` координирует близкие формы и уменьшает лишнюю работу рендера; сам не является фоновой стеклянной панелью. Его spacing управляет моментом сближения/слияния, а не обычным расстоянием `HStack`.
- Для morphing используй стабильные `glassEffectID` в namespace; `glassEffectUnion` — когда несколько форм должны составлять одну. Добавляй это при реальной потребности, не ко всем кнопкам.

Публичные основы и сигнатуры: [Applying Liquid Glass to custom views](https://developer.apple.com/documentation/swiftui/applying-liquid-glass-to-custom-views). Различай `ButtonStyle` и raw `glassEffect` на кнопке; второй сам по себе не заменяет поведение кнопки. [SwiftUI Group Lab, WWDC26, 07:21](https://developer.apple.com/videos/play/wwdc2026/8120/?time=441).

Не задавай нативному материалу вручную saturation 1.8, градиент 135°, IOR 1.5 или spring из репозитория. Эти параметры относятся к имитации. Системный appearance и пользовательский tint — разные вещи; не пытайся программно отменить выбранную пользователем плотность стекла.

## Ползунок приложения и системная настройка

Требуемый пользователем ползунок «Прозрачный → Плотный» должен регулировать реальный материал. Системный slider macOS 27 сам по себе не доказывает наличие публичного per-app API для той же регулировки. Перед реализацией проверь целевой SDK и доступные параметры; не используй private API и не меняй глобальные настройки ОС из приложения.

Если публичный API позволяет нужное управление, свяжи с ним сохраняемое значение и живое превью. Если точного аналога нет, сохраняй системное поведение нативных controls; для собственных поверхностей используй только поддерживаемую настройку с честно обозначенной областью действия. Не имитируй регулировку через opacity всего view, произвольное переключение regular/clear или принудительную замену всего native UI на custom renderer. Неподдерживаемую часть требования явно укажи пользователю; не выдавай неработающий slider за выполненную функцию.

## UIKit / AppKit

Для UIKit точка входа custom material — `UIGlassEffect` в `UIVisualEffectView`; foreground размещается в `contentView`. Для AppKit — `NSGlassEffectView`. Сначала используй системные кнопки и панели, потом custom effects. Проверяй документированную доступность container effects, corner APIs и button configurations в своей версии SDK, не копируй весь исходный пример как заведомо компилируемый.

Источники типов: [UIGlassEffect](https://developer.apple.com/documentation/uikit/uiglasseffect), [NSGlassEffectView](https://developer.apple.com/documentation/appkit/nsglasseffectview). Сниппеты репозитория при необходимости: [platforms/apple.md](../platforms/apple.md); применять после проверки сигнатур и оговорок этого документа.

## Старые ОС и другие Apple-платформы

- Runtime availability (`if #available`) и наличие API в compile SDK — разные проверки. Новый API за условием всё равно требует SDK, который его знает. Ограждай конкретные API и платформы, не объявляй поддержку всех ОС через одинаковое число версии.
- На старых ОС оставь корректный стандартный material или solid с теми же функциями; пометь его fallback. Не называй `.ultraThinMaterial`, `NSVisualEffectView` или vibrancy полноценным новым Liquid Glass.
- visionOS использует собственный пространственный контекст; tvOS — фокус и пульт; watchOS — свои размеры. Не переноси iPhone-жесты, сигнатуры и возможности автоматически.
- SwiftUI/Metal `layerEffect` обрабатывает переданный слой, а не произвольные окна позади. Custom lens над картой/картинкой — отдельный эффект; текст управления держи вне фильтруемого слоя.

## Проверка нативного результата

На целевых 26/27 проверь appearance, пользовательскую плотность стекла там, где настройка доступна, Reduce Transparency/Motion, Increase Contrast/Show Borders. Стандартный материал адаптируется системой; проверь, что custom цвета/анимации не нарушают эту адаптацию. Не заменяй все системные controls собственным solid-режимом без обнаруженной проблемы.

Нужны и светлая/тёмная темы, и прокрутка текста/медиа под контролами, и смена размеров. Финальная визуальная проверка на устройстве важнее симулятора; отсутствие Mac/Xcode в текущей среде означает «код не собран и внешний вид на Apple не проверен», а не основание выдать имитацию за нативный результат.
