# 06. Производительность

Цель: выглядеть максимально близко к оригиналу **и** держать 60/120 fps на целевом железе. Для этого эффект строится по уровням (tiers) и включается ровно настолько, насколько устройство тянет.

## 1. Уровни качества

| Tier | Что включено | Где по умолчанию |
|---|---|---|
| **T0 solid** | непрозрачная поверхность, тот же силуэт, контур, тень; без backdrop | Reduce Transparency, forced colors / высокий контраст, отсутствие backdrop-API, «Эффекты прозрачности» выключены в Windows |
| **T1 frosted** | живой backdrop: blur + saturation + fill + rim + тень + свечение касания | Safari, Firefox, слабые телефоны, Android < 12 (там — без живого blur, см. ниже) |
| **T2 lens** | T1 + рефракция кромки на ключевых элементах | Chromium-десктоп и мощные телефоны, Android 13+, Flutter Impeller, WinUI (частично) |
| **T3 liquid** | T2 + шейдерное стекло: слияние капель, аберрация, живой блик | только по явному решению: свой рендер (WebGL/Metal/Skia/Impeller), флагманы |

Правила:
- Уровень определяется **при старте** (возможности + настройки + класс устройства) и **понижается** на лету при просадках кадров. Автоматически не повышается до следующего запуска.
- Автоматически падать можно до T1, но не до T0: T0 — это выбор пользователя (доступность), а не мера производительности.
- Внешний вид между уровнями меняется плавно (≈ 0.3 с), без перестройки layout.

## 2. Модель стоимости

Стоимость живого стекла ≈ **площадь × число слоёв × радиус размытия × частота перерисовки фона**.

- **Площадь.** Главный множитель. Полноэкранный blur на телефоне — дорого; капсула 300 × 62 — дёшево.
- **Число поверхностей.** Каждая поверхность с живым backdrop — отдельное чтение фона и отдельный проход размытия. Держись бюджета (≤ 4 на мобильных, ≤ 8 на десктопе).
- **Радиус.** Растёт стоимость и ширина «захвата» фона вокруг элемента. Liquid Glass выгоден: regular — σ 10, clear — 2.
- **Рефракция.** SVG-displacement/шейдер — ещё один проход; на T2 — только ключевые элементы (≤ 2 на мобильных).
- **Перерисовка фона.** Когда контент под стеклом скроллится/анимируется, стекло пересчитывается каждый кадр. Статичный фон под стеклом — почти бесплатен (кэшируется).

## 3. Универсальные правила

1. **Не анимируй радиус размытия** и параметры фильтров покадрово. Анимируй `opacity` и `transform` слоя стекла.
2. **Не вкладывай backdrop в backdrop** (стекло на стекле): двойная стоимость, а в браузерах вложенный backdrop вообще видит только содержимое родителя.
3. **Общая поверхность для групп.** Пять кнопок тулбара — одна стеклянная капсула с пятью плоскими кнопками, а не пять стекол.
4. **Кэшируй всё, что зависит только от размера:** карты смещений, маски контура, градиенты блика. Пересчитывай после завершения ресайза (debounce ≈ 140 мс), а не на каждом кадре.
5. **Даунсэмплинг размытия.** Размывай фон в ½–¼ разрешения — на σ ≥ 8 разница не видна. Haze, Flutter, Composition, dual-Kawase делают это; в своих шейдерах — делай сам.
6. **Не рисуй стекло, которое не видно.** Скрытые/свёрнутые/за экраном элементы — без backdrop (`display: none`, `visibility`, `isVisible = false`, а не `opacity: 0`).
7. **Слой только на время анимации.** `will-change`, `graphicsLayer`, `CacheMode=BitmapCache` — включай на время анимации, не держи навсегда.
8. **Избегай стекла над видео и картами**, которые рендерятся в отдельных поверхностях (Android `SurfaceView`, нативные карты): их содержимое часто не попадает в backdrop (стекло будет пустым) или форсирует дорогой путь композиции. Используй `TextureView`/clear-вариант без blur/затемнение.
9. **Один источник правды для уровня.** Компоненты читают текущий tier из общего состояния (`html[data-lg-tier]`, `CompositionLocal`, `ThemeResource`), а не определяют его сами.

## 4. Определение уровня по платформам

| Платформа | T0 если | T1 если | T2 если |
|---|---|---|---|
| Web | `prefers-reduced-transparency`, `forced-colors`, нет `backdrop-filter` | не Chromium (нет SVG в `backdrop-filter`), `deviceMemory ≤ 2`, `saveData`, слабый touch-девайс (≤ 4 ГБ / ≤ 4 ядра) | Chromium + нормальное железо |
| Android | пользовательская настройка приложения «без прозрачности», режим высокого контраста текста | API 31–32 (`RenderEffect` blur есть, AGSL нет), `ActivityManager.isLowRamDevice()`, низкий performance class; API < 31 — T1 без живого blur (полупрозрачная заливка) | API 33+ и нормальный класс устройства |
| Windows | `UISettings.AdvancedEffectsEnabled == false`, высокий контраст | по умолчанию; режим энергосбережения | только если реализована рефракция (§2.6 windows.md) и нет энергосбережения |
| Apple | Reduce Transparency (нативный материал сам станет плотным) | — | нативный Liquid Glass (не определяем уровни, система решает) |
| Flutter | `MediaQuery.highContrast`, настройка приложения | Skia-бэкенд (нет `ImageFilter.shader`), слабое устройство | Impeller |

## 5. Автоматическое понижение

Эталон — `fpsGuard()` в [`liquid-glass.js`](../reference/web/liquid-glass.js):

```
измеряй интервалы кадров ~2.5 с (только когда вкладка видима / окно активно)
базовый интервал = 25-й перцентиль (частота дисплея: 60/90/120/144)
если доля кадров длиннее 1.8 × базового > 20 % → tier − 1 (не ниже T1)
```

Запускай измерение в моменты нагрузки (первый скролл, открытие экрана со стеклом), а не в простое. Android: `JankStats`/`FrameMetrics`; Windows: `CompositionTarget.Rendering`; Flutter: `SchedulerBinding.addTimingsCallback`.

## 6. Платформенные ловушки

**Web**
- `backdrop-filter: url(#svg)` работает только в Chromium; в Safari и Firefox — T1.
- Chromium: если у элемента с `backdrop-filter: url()` есть рендер за пределами бокса (внешний `box-shadow`, даже у потомков), фильтр **пропадает целиком**. Поэтому в эталоне backdrop живёт в `::before`, а тень — на самом элементе.
- Собственный фон элемента попадает в backdrop псевдоэлемента: у `.lg` фон должен быть пустым (иначе `<button>` размоет свой UA-фон и станет белым).
- **Backdrop Root:** предок с `opacity < 1`, `filter`, `mask`, `clip-path`, `backdrop-filter`, `mix-blend-mode` или `will-change` на них ограничивает то, что видит стекло, содержимым этого предка. Классическая ошибка — fade-in модалки через `opacity` родителя: пока идёт анимация, стекло пустое. Анимируй прозрачность самого стеклянного элемента или используй transform.
- `position: fixed` стекло над скроллящимся контентом = пересчёт каждого кадра скролла. Это нормально для 2–4 поверхностей; не делай фиксированными десятки.
- Тяжёлые SVG-фильтры не отключают GPU-растеризацию, но вызывают перерисовку; не применяй рефракцию к элементам, которые меняют размер каждый кадр.

**Android**
- `Modifier.blur()` размывает *свой* контент, а не фон. Для фона нужен захват слоя (Haze, своя `GraphicsLayer`).
- `RenderEffect` — API 31+, `RuntimeShader` (AGSL) — API 33+.
- `SurfaceView` (видео, камера, карты) не попадает в захват слоя.
- Cross-window blur (`blurBehindRadius`) может быть выключен системой (`WindowManager.isCrossWindowBlurEnabled`) и выключается в режиме энергосбережения — всегда имей fallback-заливку.

**Windows**
- WinUI 3 `AcrylicBrush` — только in-app (размывает содержимое окна). Для фона за окном — `DesktopAcrylicBackdrop`/`MicaBackdrop` (`SystemBackdrop`).
- Кастомные Composition-кисти **не** выключаются автоматически при отключённой прозрачности в системе — проверяй `UISettings.AdvancedEffectsEnabled` сам и подписывайся на изменения.
- WPF `VisualBrush` + `BlurEffect` перерисовывают источник: для динамичного фона дорого, кэшируй (`BitmapCache`) и ограничь площадь.

**Flutter**
- Каждый `BackdropFilter` — отдельный проход. Для нескольких стеклянных элементов на одном фоне используй `BackdropGroup` + `BackdropFilter.grouped` (Flutter 3.29+), они делят одну выборку фона.
- Всегда оборачивай `BackdropFilter` в `ClipRRect`/`ClipRSuperellipse`, иначе размывается весь экран.

**Apple**
- Нативный материал уже оптимизирован. Не имитируй его поверх (`.ultraThinMaterial` + свои блики) на 26+ — это дороже и хуже.
- Много отдельных `.glassEffect()` без контейнера — медленнее, чем в одном `GlassEffectContainer`.

## 7. Профилирование: что смотреть

| Платформа | Инструмент | Метрика |
|---|---|---|
| Web | DevTools → Performance (CPU ×4 throttling), Rendering → Frame Rendering Stats, Layers | длинные кадры, GPU-время, число композитных слоёв |
| Android | Perfetto / Android Studio Profiler, GPU rendering bars, `JankStats` | janky frames %, RenderThread время |
| Windows | Visual Studio → Performance Profiler (GPU Usage), PIX, WinUI `DebugSettings.EnableFrameRateCounter` | время кадра, композитор |
| Apple | Instruments → Animation Hitches, Core Animation | hitch time ratio |
| Flutter | DevTools → Performance, `--profile`, raster thread | raster time > budget |

Проверка перед сдачей: самый слабый целевой девайс/профиль, скролл длинного списка под таб-баром и тулбаром, открытие меню и шторки, быстрые повторные тапы — без устойчивых просадок ниже частоты дисплея.
