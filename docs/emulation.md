# Другие платформы: построение материала

Прочитай общую часть и только раздел своего стека. Здесь инженерные рекомендации для имитации, а не внутренний рендерер Apple. Наличие шейдера не подтверждает доступ к нужным пикселям.

## Контракт рендеринга

До выбора библиотеки установи три вещи: **откуда берётся backdrop, когда он обновляется, в каких координатах его читает стекло**. Источник должен исключать сам эффект и его foreground, иначе возможны самозахват и повторное размытие.

Слои компонента:
1. Реальный контент/доступная texture и внешняя тень формы.
2. Выборка фона с edge displacement и рассеиванием.
3. Адаптивная нейтральная заливка, смысловой tint, свет/кромка.
4. Чёткий foreground и отдельные состояния focus/disabled/selected.

Возможна перестановка проходов blur/refraction ради производительности, но вид изменяется: сравни результат с референсом, не считай эти операции коммутативными. Преломление ориентируй по нормали формы, ослабляй к центру; turbulence не заменяет профиль линзы. Законы Снеллиуса/SDF из репо — полезная модель, не доказательство устройства материала Apple.

При реализации шейдера:
- свяжи local coordinates с texture coordinates, scroll/resize/transform и DPR; не смешивай DIP/CSS px/physical pixels;
- используй расширенную область выборки для blur и смещения, затем clip конечной формы; иначе край темнеет или обрезается;
- обработай нулевой градиент SDF без `normalize(0)`, нулевые размеры, слишком большой radius, границы texture;
- согласуй sRGB/linear и premultiplied alpha с API; не применяй яркость, tint или saturation дважды;
- кэшируй геометрию/карты, но не замораживай движущийся backdrop; foreground не входит в blur/displacement;
- chromatic aberration и следование света курсору по умолчанию выключены. Добавляй лишь при наличии такого эффекта в ориентире; радужная кромка не является универсальным признаком Apple.

Формулы и переносимые заготовки: [оптика upstream](../docs/03-optics.md), [шейдеры и примеры](../AGENTS.md). По последней ссылке используй таблицу путей, а не старые обязательные правила.

## Токены и калибровка

### Сначала исключи потерю прозрачности

Проверь **весь путь до видимого фона**: фон окна/экрана → scroll-edge veil → material underlay → tint → selected/hover overlay. Для независимых обычных alpha-заливок остаток исходного фона равен `T = ∏(1 − alpha_i)`, итоговая покрывающая alpha — `1 − T`. Например, слои .30 и .78 оставляют лишь 15.4% исходного сигнала. Для Acrylic с luminosity/compositing формула не заменяет проверку рендера.

1. Временно убери декоративные заливки у одного компонента. Покажи под ним двигающиеся цветные области, наклонные линии и текст. Если фон не виден уже здесь, исправляй источник/порядок слоёв, а не увеличивай strength шейдера.
2. Проверь blur отдельно при выключенной линзе: границы фона смягчаются, foreground остаётся резким. Затем включи линзу при неизменных остальных параметрах: линии у кромки должны менять положение. Наклонные линии выявляют эффект лучше линий, параллельных нормали смещения.
3. Верни минимальную заливку и проверь реальный экран. Для **прозрачного custom-контрола** инженерная отправная точка — neutral alpha около .06–.16 light / .08–.20 dark и blur около 2–6 CSS px в web. Это не норма Apple, не универсальные Android dp и не обязательные значения: калибруй их по размеру, фону и референсу. Не начинай с .7–.96 на всей панели, если пользователь просит прозрачное стекло.
4. Большой blur после displacement может стереть изгиб кромки. Не усиливай оба параметра без сравнения; проверь меньший blur или раздельное рассеивание центра/кромки. Профиль линзы привязан к форме, не к случайному шуму.

Готовое [сравнение на живом DOM-фоне](../reference/web/optics.html) использует тот же SVG renderer: плотная заливка, прозрачный blur и прозрачный blur с линзой. Запускай через локальный HTTP-сервер; сдвиг фона, ползунок плотности, темы, сохранение и Reduce Transparency доступны прямо в примере. Это диагностический пример, не визуальный эталон Apple. Переноси настройки в продукт только после проверки его фонового слоя.

Используй [JSON репозитория](../tokens/liquid-glass.tokens.json) как **начальное приближение 26**, затем сделай проектный набор override-токенов. Снимок upstream не редактируй ради настройки отдельного продукта. Храни вариант, тему, состояние и единицы в одном модуле; избегай независимого подбора каждого экземпляра.

| Исходный вариант репо | Blur σ | Fill light / dark |
|---|---|---|
| regular | 10 | `rgb(255 255 255 / .20)` / `rgb(30 30 34 / .36)` |
| clear | 2 | `rgb(255 255 255 / .06)` / `rgb(0 0 0 / .08)` |
| thick, проектный плотный вариант | 24 | `rgb(248 248 250 / .72)` / `rgb(40 40 44 / .72)` |
| solid, исправленный доступный вариант | 0; sampling off | `rgb(249 249 251)` / `rgb(28 28 30)`, alpha **1** |

Saturation `1.8`, brightness `1.05/.92`, фон `#F2F2F7/#000000` — тоже стартовые числа репо, не требования Apple. Веб `blur()` и платформенный blur API проверяй по их определению единиц; не переноси радиус вслепую.

Исходный rim — около 1 логической единицы, белый градиент 135° с alpha light `.90/.14/.14/.50`, dark `.50/.06/.06/.24`. Подбирай толщину и интенсивность по масштабу, фону и референсу. Избегай яркой сплошной рамки вокруг каждого элемента; контрастный focus outline имеет отдельную функцию и может быть сплошным.

Для **профиля 27** исходные токены требуют калибровки: отдели параметры рассеивания, тёмной кромки, светового блика и плотности. Не трактуй изменения поколения как требование непрозрачной заливки. Качественный ориентир — [Apple WWDC26 Keynote, раздел design](https://developer.apple.com/videos/play/wwdc2026/101/); точных чисел Apple этот источник не даёт.

Настраивай в таком порядке: геометрия и реальный backdrop → рассеивание/контраст → сила edge lensing → кромка/тень → tint → движение. Меняй один связанный набор параметров за раз, сравнивая одинаковые состояния. На маленьком компоненте используй сдержанную кромку; одна широкая линза на всех размерах даёт «желе». Расположение света может различаться по теме и компоненту.

Адаптивность может использовать семантический тип участка фона или дешёвую оценку яркости texture. Средняя яркость не доказывает контраст на пёстром фоне. Проверь контраст в движении и при необходимости локальную защиту foreground; не повышай непрозрачность всех панелей лишь из-за неопределённости. Гистерезис предотвращает мелькание светлого/тёмного режима. Не делай GPU readback каждый кадр ради цвета текста.

## Регулировка Liquid Glass в настройках

Используй один сохраняемый параметр плотности, например `glassDensity` в диапазоне 0…1: 0 — прозрачный вид, 1 — плотный. Эти числа — внутренний контракт приложения, не шкала или константы Apple. Подписи для пользователя: «Liquid Glass», «Прозрачный», «Плотный»; действие сброса — «По умолчанию».

- Откалибруй прозрачный и плотный варианты для light/dark и ролей материала. По значению ползунка плавно меняй нейтральную заливку и необходимые параметры рассеивания/света между ними. Не интерполируй вслепую все токены; акцентный цвет действия, геометрия, foreground и motion остаются независимыми.
- Не применяй `opacity` к панели вместе с текстом. Не умножай силу всех эффектов на значение: 0 не означает исчезновение материала или линзы, 1 не означает максимальные blur и distortion. Доступный renderer T1/T2 выбирается отдельно.
- Применяй настройку через общий материал/тему ко всем соответствующим поверхностям. Превью рядом с ползунком использует тот же renderer на небольшом репрезентативном фоне; по нему виден реальный эффект, а не декоративный градиент.
- Обновляй превью и приложение во время перетаскивания, не чаще кадра; дорогие карты геометрии не пересоздавай от изменения плотности. Если меняется blur, проверь стоимость обновления и используй дешёвый путь регулировки при необходимости. Запись в существующее хранилище настроек выполняй с debounce или по завершении ввода; итоговое значение восстанавливай до первой видимой отрисовки материала, где это позволяет стек.
- Сохраняй предпочтение существующим механизмом проекта; для локального web-приложения подходит localStorage с обработкой недоступности. Проверь диапазон и некорректные сохранённые данные, используй проектный default. Не вводи аккаунты или сетевую синхронизацию только ради этого параметра.
- Используй стандартный доступный slider с названием, понятным текущим значением и клавиатурным управлением. При Reduce Transparency/forced colors применяй обязательный fallback, сохраняя выбранное значение для последующего восстановления; объясни рядом, почему регулировка сейчас недоступна. Защитный контраст сохраняется во всём диапазоне.

## Web, Electron, Tauri

- Для диагностики выдели T1 на реальном `backdrop-filter`, затем проверь T2 до распространения материала. Это фильтр области позади элемента; обычный `filter` фильтрует его собственное изображение. Учитывай stacking context, backdrop root, clipping, прозрачность предков и порядок псевдоэлементов. [MDN backdrop-filter](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/backdrop-filter).
- SVG displacement через `backdrop-filter: url(#…)` включай только после **проверки отрисовки в целевых версиях движка**. `CSS.supports` проверяет принятие синтаксиса; user-agent/название Chrome не доказывают работу конкретного filter graph. При отсутствии доказательства сохраняй T1.
- Для SVG: нейтральная карта R/G=.5, alpha=1, `color-interpolation-filters="sRGB"`; масштаб и размер карты соответствуют компоненту. Проверь тень, transforms, scroll и shadow DOM; локальные SVG ids должны разрешаться и быть уникальными.
- Реальный T2 означает изгиб движущейся сетки **под** стеклом при неподвижной чёткой надписи **на** нём. Скриншот/размеченные секции могут помочь оформлению, но не заменяют живое sampling.
- Для собственного canvas/WebGL/WebGPU-фона можно сделать полноценные проходы blur, SDF/refraction, lighting. Произвольный DOM не становится texture автоматически. Не подменяй его копией wallpaper; DOM-to-canvas snapshots ограничены обновлением, шрифтами, видео и CORS.
- WebView проверяй по фактическому движку и его версии. Нативный фон окна/vibrancy/Mica не добавляет нативный Apple glass DOM-элементам.
- Сохрани semantic HTML, tab order, focus, hit targets, клавиатуру и touch; применяй обработчики с cleanup при unmount. Эффект не должен перехватывать клики, мешать drag/scroll или ломать SSR.
- Проверяй media queries доступности и их изменения во время работы. Если системная настройка не доступна браузеру, для заметного собственного эффекта уместна настройка приложения «уменьшить прозрачность/движение». Не считай отсутствие API разрешением игнорировать fallback.

Код брать выборочно из [web-гайда](../platforms/web.md), [CSS](../reference/web/liquid-glass.css), [JS](../reference/web/liquid-glass.js); для собственного render target — [WebGL](../reference/web/liquid-glass-webgl.js).

## Windows: Mica, Acrylic, Composition, WPF

**Mica** — базовый материал окна с влиянием обоев, не живая линза над окнами позади. **Acrylic** — материал Fluent с размытием; бывают системный backdrop и in-app usage. Они полезны по своей роли, но не подтверждают воспроизведение оптики Apple. [Microsoft Mica](https://learn.microsoft.com/en-us/windows/apps/design/style/mica), [Microsoft Acrylic](https://learn.microsoft.com/en-us/windows/apps/design/style/acrylic).

Для WinUI 3 настройка `AcrylicBrush.TintOpacity` меняет тонировку, **не добавляет refraction**. Проверь также `TintLuminosityOpacity`, fallback, системные эффекты и непрозрачный canvas под панелью. Ползунок с default .68, преобразуемым в tint .82, уже даёт плотный материал независимо от названия «Liquid Glass». Если проект остаётся на Acrylic, честно называй результат прозрачным Acrylic/T1; для линзы нужен отдельно проверенный renderer. [AcrylicBrush, Windows App SDK](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.xaml.media.acrylicbrush).

- Для WinUI/Composition документируй, какие visuals доступны `CompositionBackdropBrush`. Это не произвольный захват desktop. SystemBackdrop и in-app brush имеют разные источники. [Microsoft API](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.composition.compositionbackdropbrush).
- Gaussian blur + ColorMatrix + fill дают T1. Масштабирование полосы у края не доказывает пространственно изменяющуюся рефракцию. Для T2 нужны допустимый input, поддерживаемый effect/shader graph и тест сеткой. Не придумывай API displacement.
- WPF: копируй только отдельный фон через `VisualBrush`/render target; blur и `ShaderEffect` применяй к этой копии. `ContentPresenter`, фокус и overlay находятся **вне** фильтруемого контейнера. Источник не содержит стекло. Обновляй viewbox/transform при движении, scroll и DPI.
- WinForms/GDI, Avalonia/Skia, Uno имеют разные возможности. Проверяй реальный backend, версии пакетов и поддержку backdrop sampling. Название Skia или наличие `RuntimeEffect` ещё не дают текстуру всего окна.
- Сохраняй titlebar drag regions, системные кнопки, Snap, keyboard navigation, IME и hit-testing. Изменение чужих окон/desktop не требуется для эффекта внутри приложения.

Сниппеты: [Windows-гайд](../platforms/windows.md). Не копируй его WPF `Grid.Effect` вокруг `ContentPresenter` (см. ниже).

## Android, Flutter и остальные

| Стек | Что необходимо подтвердить до заявления о T2 |
|---|---|
| Android Compose/Views | У слоя есть копия нужного backdrop. `RenderEffect` на кнопке фильтрует кнопку; `RuntimeShader` без input не видит соседние views. API 31/33 и версии Compose проверяются отдельно. |
| Flutter | `BackdropFilter` и `ImageFiltered` имеют разные источники. Для `ImageFilter.shader` проверь `ImageFilter.isShaderFilterSupported`, backend и uniform layout (первый vec2 — размер, первый sampler — input). API ограничен Impeller; на GLES учти направление Y. Не объявляй T2 на всех desktop/web-targets по названию Flutter. |
| React Native/Expo/MAUI | Нативный модуль стекла и fallback выбираются по ОС и версии пакета. JS-имитация внутри WebView остаётся web; bridge должен передавать размер, состояния и accessibility. |
| Qt/Skia/движки | Нужны явная текстура сцены/слоя, корректная синхронизация, координаты и порядок рендера. Текст управления рисуется после эффекта. |

Документы: [Android AGSL](https://developer.android.com/develop/ui/views/graphics/agsl/agsl-vs-glsl), [Flutter ImageFilter.shader](https://api.flutter.dev/flutter/dart-ui/ImageFilter/ImageFilter.shader.html).

На Android проверь фактически исполненный путь каждого нужного компонента: включены ли capture, blur и lens именно у toolbar/navigation, а не только у тестовой панели. Режим настроек «Полный» или наличие `lens()` в исходнике этого не доказывают. Проверь screen/Surface backgrounds, chrome veil, underlay, tint, восстановленную плотность и флаги performance tier. Если после добавления скилла вид стал хуже, сравни исходный материал и новую композицию до дальнейшей настройки. `RenderEffect` получает содержимое связанного RenderNode, поэтому источник backdrop должен быть сформирован отдельно от foreground. [Android RenderEffect](https://developer.android.com/reference/android/graphics/RenderEffect).
Сниппеты нужного стека: [Android](../platforms/android.md), [Flutter](../platforms/flutter.md), [остальные](../platforms/cross-platform.md).

## Ограничения исходных примеров

Ниже — находки чтения кода версии `d6dacca8`, а не результаты запуска на всех платформах.

| Место | Ограничение и действие |
|---|---|
| `liquid-glass.js: detectTier()` | T2 назначается после проверки Chromium и ресурсов, без pixel-test SVG. Считай его кандидатом; сначала проверь реальные пиксели. |
| CSS `--lgv-solid` и `.lg:not(.lg-prominent)` | Solid имеет alpha .97, prominent исключён из части замен. При Reduce Transparency/T0 сделай **все** варианты непрозрачными, выключи их фильтры, проверь thumb/scroll edge и активные состояния. |
| `initLiquidGlass({tier})` | Явный tier не проходит заново через detectTier. Приоритет доступности должен оставаться выше принудительного качества и пользовательских переключателей. |
| `fpsGuard()` | Минимум автоматического понижения — T1; интервалы сравниваются с собственной наблюдаемой частотой. Ровные 30 fps на 60 Hz могут не выглядеть как просадка. Измеряй против бюджета целевого дисплея, разрешай T0 при необходимости, избегай переключений туда-сюда. |
| WPF `Grid.Effect` в windows.md §3.2 | В том же Grid находится `ContentPresenter`, поэтому эффект захватывает foreground. Вынеси foreground в соседний верхний слой. |
| `visual-check.mjs` | Снимает Chromium и интервалы rAF. Не сравнивает с Apple, не доказывает рефракцию/контраст, не тестирует другие движки и не гарантирует падение процесса при ошибках страницы. Читай report/errors и сами изображения. |

Остальные платформенные примеры не имеют здесь гарантии сборки. Не подключай весь upstream как dependency и не переписывай проект ради его классов. Перенеси минимально нужную логику и примени оговорки выше в проектной копии.
