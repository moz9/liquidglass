# 03. Оптика: как считать преломление, блик и слияние

Одна модель для всех платформ. Эталонные реализации:
- CPU-карта смещений (для SVG/Win2D/Skia displacement map): [`reference/web/liquid-glass.js`](../reference/web/liquid-glass.js) — `refractionProfile()`, `displacementMap()`;
- GPU-шейдер (для WebGL, AGSL, Flutter, HLSL, движков): [`reference/shaders/`](../reference/shaders/).

## 1. Форма: SDF

Каждая стеклянная форма описывается знаковым расстоянием (signed distance field, SDF): `d(p) < 0` внутри, `0` на контуре, `> 0` снаружи.

```glsl
// p — точка относительно центра, b — половина размера, r — радиус угла
float sdRoundRect(vec2 p, vec2 b, float r) {
  vec2 q = abs(p) - b + r;
  return min(max(q.x, q.y), 0.0) + length(max(q, 0.0)) - r;
}
```

Капсула — это `sdRoundRect` с `r = min(b.x, b.y)`, круг — с `b.x = b.y = r`.

**Нормаль** (наружу) — градиент SDF, достаточно центральных разностей с шагом 0.5 px:

```glsl
vec2 n = normalize(vec2(d(p + (0.5,0)) - d(p - (0.5,0)), d(p + (0,0.5)) - d(p - (0,0.5))));
```

## 2. Слияние капель: smooth union

Когда две формы ближе `k` (токен `mergeDistance`, 24), они сливаются в одну с плавной «шейкой»:

```glsl
float smin(float a, float b, float k) {
  float h = max(k - abs(a - b), 0.0) / k;
  return min(a, b) - h * h * k * 0.25;
}
float scene(vec2 p) { return smin(sdA(p), sdB(p), k); }  // для N форм — свёртка по очереди
```

Так ведёт себя `GlassEffectContainer(spacing:)` в SwiftUI. В DOM/XAML/Views без шейдера настоящего слияния нет — см. обходные пути в [05-motion.md](05-motion.md#7-слияние-и-разделение).

## 3. Рефракция

Стекло — плоская пластина с выпуклой кромкой шириной `bezel`. Параметр `t = clamp(−d / bezel, 0, 1)`: 0 на самом краю, 1 там, где начинается плоская середина.

**Профиль высоты кромки** (выпуклый суперэллипс):

```
h(t) = (1 − (1 − t)^p)^(1/p),   p = 3   (2 — круг, 4 — «squircle» с более плоским центром)
```

**Закон Снеллиуса.** Луч смотрит перпендикулярно экрану и падает на наклонную поверхность кромки. Угол наклона `θ = atan(h'(t))`, угол преломления `θt = asin(sin θ / n)`, `n = 1.5`. Отклонение луча `δ = θ − θt`, боковое смещение пропорционально `tan δ`. Нормируем на максимум у самого края (там `θ = 90°`):

```
D(t) = tan(θ(t) − θt(t)) / tan(90° − asin(1/n))        // 1 на краю, 0 в плоской середине
offset(p) = −n̂(p) · D(t) · strength                    // ВНУТРЬ: выпуклая кромка сводит лучи к центру
sample = backdrop(p + offset)
```

Почему внутрь: нормаль поверхности на кромке наклонена наружу, преломлённый луч отклоняется к центру и попадает в фон ближе к середине. Визуально фон у кромки «растягивается» к краю, линии изгибаются дугами, у самого края возможен узкий отражённый участок — это правильно.

`strength` — максимальное смещение в пикселях (`bezel × 1.0`). Больше — сильнее «линза», но появляются складки у края; меньше 0.6 × bezel эффект почти не читается.

### 3.1. Карта смещений (для SVG `feDisplacementMap`, Win2D, Skia, Qt)

Если у платформы нет шейдеров над фоном, но есть displacement-фильтр — посчитай карту на CPU **один раз на размер** и кэшируй:

```
R = 0.5 + dx / 2,  G = 0.5 + dy / 2,  где (dx, dy) = −n̂ · D(t) ∈ [−1, 1]
B = 0.5 (не используется), A = 1
scale фильтра = 2 × strength
```

`feDisplacementMap` сдвигает выборку на `scale × (C − 0.5)`, поэтому смещение получится ровно `strength × dx`.

Обязательно:
- `color-interpolation-filters="sRGB"` на фильтре — иначе браузер переведёт карту в linearRGB и все смещения будут неверны;
- размер карты = размер элемента в CSS px (не умножай на DPR: карта гладкая, 1× достаточно);
- кэш по ключу `(w, h, radius, bezel, strength, p, n)`; при изменении размера — сразу убрать фильтр и пересчитать после паузы ≈ 140 мс (устаревшая карта гнёт не те пиксели).

### 3.2. Хроматическая аберрация

Только на T3 и едва заметно: три выборки со смещениями `offset × (1 + a)`, `offset`, `offset × (1 − a)` для R, G, B, `a = 0.08`. На T2 выключено (в SVG это втрое дороже).

## 4. Материал поверх выборки

```glsl
col = blurredBackdrop(p + offset);                  // σ из токенов; blur ДО или ПОСЛЕ смещения — оба варианта ок
col = mix(vec3(luma(col)), col, 1.6..1.8);          // насыщенность
col *= brightness;                                  // 1.05 light / 0.92 dark
col = mix(col, fillColor, fillAlpha);               // адаптивная заливка
col = mix(col, tint.rgb, tint.a);                   // tint, если есть
```

## 5. Спекулярный блик

Свет по умолчанию сверху-слева: `L = normalize(−0.6, −0.8)` (экранные координаты, y вниз).

```glsl
float facing = dot(n, L);                           // n — нормаль наружу
float rim    = 1.0 - smoothstep(0.0, 1.6, -d);      // тонкая линия ~1.5 px по контуру
float sheen  = pow(1.0 - t, 3.0);                   // широкий мягкий блик внутри кромки
float spec   = rim * (0.3 + 0.7 * max(facing, 0.0) + 0.45 * max(-facing, 0.0))
             + sheen * 0.16 * (0.5 + 0.5 * facing);
col += spec * (dark ? 0.55 : 0.9);
```

Противоположная сторона тоже светится (слабее): свет, вошедший с одной стороны, выходит с другой. Без шейдеров то же даёт градиентная обводка 135° (см. токены rim).

**Динамический блик (опционально, T3):** на мобильных направление света слегка вращается от наклона устройства (гироскоп, фильтр низких частот, ±15°), на десктопе — едва заметно следует за курсором. При Reduce Motion — статичен.

## 6. Тень и сглаживание

- Тень снаружи формы: `shadow = (1 − smoothstep(−4, 22, d(p − (0, 6)))) × 0.16` (light) / `0.34` (dark).
- Край: `coverage = clamp(0.5 − d, 0, 1)` и смешивание с внешним цветом — бесплатное сглаживание силуэта без MSAA.

## 7. Размытие в шейдерах

Размывать фон попиксельно в том же шейдере дорого. Варианты по убыванию предпочтительности:
1. Отдать размытие платформе и применить шейдер к уже размытому фону: Android — `RenderEffect.createChainEffect(shader, blur)`, Flutter — `ImageFilter.compose`, Composition — `GaussianBlurEffect` в графе.
2. Отдельный проход: downsample ×2–4 + dual Kawase / separable Gauss в текстуру, затем шейдер читает размытую текстуру (эталон WebGL — предразмытая текстура).
3. `textureLod` по мип-уровням (дёшево, но заметны ступеньки при движении).

## 8. Адаптивный вид (light/dark)

- Нужна средняя относительная яркость фона *под элементом* `Y = 0.2126 R + 0.7152 G + 0.0722 B` (линейный RGB).
- С гистерезисом: `Y < 0.4 → dark`, `Y > 0.6 → light`, между — не менять. Переход ≈ 0.3 с.
- Как получить `Y` дёшево: на GPU — самый маленький мип фона или 1 × 1 downsample (без readback в каждом кадре — раз в 100–200 мс или по окончании скролла); в DOM — не читать пиксели вообще, а размечать секции страницы (`data-lg-surface="dark|light|auto"`) и смотреть, какая секция под элементом (эталон `adaptiveAppearance()`).

## 9. Калибровка «на глаз»

1. Поставь элемент на три фона: белый с текстом, чёрный, пёстрое фото или полосы.
2. На сетке из тонких линий (шаг 16 px) проверь рефракцию: в центре линии прямые, у кромки плавно изгибаются, в углах — дугами. Складки и разрывы → уменьши `strength` или увеличь `p`.
3. Над белым стекло почти белое с тенью и бликом, над чёрным — тёмно-серое с ярким контуром, над фото цвета фона насыщенно просвечивают. Текст читается во всех трёх случаях.
